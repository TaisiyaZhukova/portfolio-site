    Финальное задание. Часть 1. Создание лабораторной работы с помощью LLM

    Задача: с использованием большой языковой модели (ChatGPT, YandexGPT и др.) разработать лабораторную работу для студентов педагогического направления по инструменту SQLite. Тематика: динамическая типизация, транзакции, индексы.

    1. Первоначальный промт

    Ниже приведён полный текст промта, который был сформулирован с учётом методических требований и типовых недочётов.

    Ты преподаватель дисциплины «Информационные системы и базы данных» и разрабатываешь лабораторную работу для студентов педагогического направления, которые в будущем смогут преподавать дисциплины, связанные с базами данных.

Необходимо разработать одну лабораторную работу по инструменту SQLite.

Лабораторная работа должна быть рассчитана на выполнение в течение 4–8 академических часов (1–2 аудиторных занятия и 2–4 часа самостоятельной доработки и оформления результатов). Задания должны быть конкретными, выполнимыми, воспроизводимыми и не должны допускать неоднозначного толкования.

В лабораторной работе необходимо рассмотреть не более трёх особенностей SQLite. Предпочтительно использовать следующие аспекты:

- динамическая типизация данных (type affinity);

- влияние транзакций на производительность массовой вставки;

- влияние индексов на скорость поиска.

Сформулируй лабораторную работу в следующей структуре:

1.  Название лабораторной работы.

2.  Цель работы.

3.  Перечень изучаемых особенностей SQLite (не более трёх).

4.  Используемые программные средства.

Для каждого программного средства укажи:

- название;

- версию (или минимальную рекомендуемую версию);

- является ли инструмент обязательным или допускается замена;

- альтернативные варианты (если допустимы).

Например:

- Python 3.12 или новее;

- модуль sqlite3 стандартной библиотеки Python;

- DB Browser for SQLite;

- Visual Studio Code или PyCharm Community Edition.

Последовательность выполнения лабораторной работы.

Сформулируй 5–7 шагов.

Для каждого шага обязательно укажи:

- цель шага;

- какие программы или инструменты используются;

- конкретные команды SQL или фрагменты кода Python, если они необходимы;

- количество записей, которое требуется создать;

- каким способом следует измерять время выполнения (если требуется измерение);

- сколько измерений необходимо выполнить;

- что именно должно получиться в результате выполнения шага;

- в каком виде студент должен представить результат (скриншот, таблица, файл базы данных, листинг программы и т.д.).

Запрещается использовать формулировки:

- «измерьте время» без указания способа измерения;

- «создайте много данных» без указания количества записей;

-   «продемонстрируйте результат» без указания формы представления результата;

- «используйте любой инструмент» без перечисления допустимых программ.

Укажи:

- какие файлы должны быть приложены;

- какие скриншоты необходимо сделать;

- какие таблицы с результатами должны быть заполнены;

Укажи:

- рекомендуемую продолжительность;

- последовательность демонстрации;

- какие окна программ должны быть показаны;

- какие результаты должны быть озвучены.

Критерии успешного выполнения каждого пункта.

Для каждого задания опиши, по каким признакам преподаватель сможет определить, что оно выполнено.

Ограничения.

Лабораторная работа должна:

- выполняться на одном персональном компьютере;

- не требовать установки серверных СУБД;

- не требовать использования многопоточности, если результат зависит от особенностей операционной системы;

- не содержать задач, выполнение которых может оказаться нестабильным или трудно воспроизводимым;

- не требовать построения графиков, если достаточно таблиц с результатами.

После формирования лабораторной работы выполни самопроверку и перечисли возможные неоднозначности.

Для каждого обнаруженного недостатка укажи:

- в чём заключается проблема;

- почему студент может понять задание по-разному;

- как необходимо изменить формулировку, чтобы неоднозначность исчезла.

    Шаг 1. Создание базы данных и заполнение таблицы для исследования динамической типизации

    Цель

    Изучить поведение SQLite при сохранении данных различных типов.

    Используемые средства

    • Python 3.12;

    • sqlite3;

    • DB Browser for SQLite (для просмотра результатов).

    Необходимый код

    import sqlite3

con = sqlite3.connect("lab.sqlite")
cur = con.cursor()

cur.execute("""
CREATE TABLE products(
    id INTEGER PRIMARY KEY,
    quantity INTEGER,
    price REAL,
    code TEXT
)
""")

rows = [
    (10, 15.5, "A101"),
    ("25", 20.7, "B202"),
    (8.9, "30.5", 100),
    ("abc", 45, "C303"),
    (None, None, None)
]

cur.executemany(
    "INSERT INTO products(quantity, price, code) VALUES (?, ?, ?)",
    rows
)

con.commit()
con.close()

    Количество записей

    5 записей.

    Измерение времени

    Не требуется.

    Результат

    Создана база данных lab.sqlite, содержащая таблицу products.

    Представление результата

    • файл lab.sqlite;

    • листинг программы;

    • скриншот таблицы в DB Browser for SQLite.

    5.1. Тест по теории SQLite (4 вопроса)

    Вопрос 1. В SQLite понятие "Type Affinity" (динамическая типизация) означает, что:

    a) Все данные в столбце должны строго соответствовать типу, указанному при создании таблицы.

    b) Тип данных определяет максимальный размер хранимого значения.

    c) Столбец имеет рекомендуемый тип, но может хранить значения любого типа, которые SQLite попытается преобразовать к этому типу.

    d) Тип данных определяется только на основе первой вставленной записи.

    Вопрос 2. Вы создаете таблицу CREATE TABLE test (id INTEGER PRIMARY KEY, value TEXT); и вставляете запись INSERT INTO test (value) VALUES (12345);. Каким будет результат выполнения запроса SELECT value, typeof(value) FROM test;?

    a) 12345 | integer

    b) 12345 | text

    c) '12345' | text

    d) 12345 | null

    Вопрос 3. В чем заключается основная причина значительного ускорения массовой вставки (например, 15 000 записей) при использовании одной транзакции (BEGIN; ... COMMIT;) по сравнению с автоматическим коммитом после каждой записи?

    a) Индексы временно отключаются во время транзакции.

    b) Данные сжимаются перед записью на диск.

    c) Операции записи на диск (синхронизация журнала) выполняются один раз в конце транзакции, а не 15 000 раз.

    d) SQLite использует многопоточность внутри одной транзакции.

    Вопрос 4. Предположим, у вас есть таблица orders с 1 миллионом записей. Вы часто выполняете запросы SELECT * FROM orders WHERE customer_id = ? AND order_date > ?;. Какой индекс будет наиболее эффективным для ускорения этого конкретного запроса?

    a) CREATE INDEX idx_customer ON orders(customer_id);

    b) CREATE INDEX idx_date ON orders(order_date);

    c) CREATE INDEX idx_customer_date ON orders(customer_id, order_date);

    d) Создание индексов не повлияет на скорость, так как SQLite не использует их для составных условий.
